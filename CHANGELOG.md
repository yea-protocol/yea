# Changelog

## v0.1.0: first public draft

YEA (*Your Explicit Approval*) was developed as Parley before its first release, and renamed to avoid clashing with other AI-agent projects.

- **Spec v1 draft:** six verbs (`HELLO`, `ASK`, `INTENT`, `COMMIT`, `UNDO`, `EXPAND`), proposals with effects, cost, risk and undo windows, policy-gated auto-commit, grants (Ed25519 capability chains) with hash-bound consent, token budgets, and Lens, the canonical model-facing text format.
- **TypeScript reference** (`@yea-protocol/sdk` on npm, with the `yea` command in `@yea-protocol/cli`): zero dependencies. Service and client, TCP/TLS/stdio/HTTP transports, the `yea` CLI, and an MCP bridge for Claude Code and other MCP clients.
- **Python implementation** (`yea-sdk` on PyPI, `import yea`): passes every conformance vector and interoperates with TS in both directions.
- **OpenAPI adapter:** `yea openapi <spec>` serves any REST API as a YEA service, with writes as previewed, consent-gated proposals.
- **One-command setup:** `yea install` registers the MCP bridge and agent instructions with Claude Code, Claude Desktop, Cursor, Windsurf, Gemini CLI, VS Code and Codex. `yea doctor` checks everything, and `yea uninstall` restores configs byte-for-byte. `yea install --require-interaction` (or `YEA_REQUIRE_INTERACTION=1`, which the plugin passes on) makes Claude Code prompt for every call of a tool that changes things, even in `auto` or `bypassPermissions`; it's off by default ([#338](https://github.com/yea-protocol/yea/issues/338)).
- **`yea test-drive`:** watch a real Claude model use YEA live through the bridge `yea mcp` serves, approving its purchases in your terminal. It approves in its own loop, never in the agent's tools, and its throwaway principal stays in memory ([#299](https://github.com/yea-protocol/yea/issues/299)).
- **Short ids for `yea approve`:** a tool result that can't ask in the client gives a short id with each consent code, so on one account the person runs `yea approve <id>` in a terminal outside the chat, and nothing goes back through it; `yea approve` alone lists what's pending. That's a convenience for one account, and form tier there; another OS user or device uses the whole code. A protocol consent still expires with its proposal, and when that's over an hour away `yea approve` says so before the y/N ([#325](https://github.com/yea-protocol/yea/issues/325)).
- **Closed options:** in `@yea-protocol/mcp`, `yea()`, `job()`, `guard()`, `bridge()`, `httpApp`, `httpGate` and `serveHttp` refuse an unknown option, a missing required one, or one of the wrong type, naming it, before anything is registered, served or written; a malformed `tighten` option stops start-up instead of being dropped with a warning, and `bridge()` refuses `tighten.outOfBand`, which it can't honour. `job()` takes `_meta` and `icons`, and `guard()` its own `requireInteraction`. In `yea-mcp`, the `tighten` and `annotations` dicts and `risk` are checked the same way, and `guard()` takes `require_interaction` ([#368](https://github.com/yea-protocol/yea/issues/368)).
- **A total per period:** a `total` limit can take `every`, so a person signs "at most 500 USD a week" once: it counts in fixed periods from its grant block's one `nbf`, and needs an `exp` in that block or an earlier one. `yea grant --total spend=500USD/7d --exp 90d` issues it, and `yea grant` and `yea inspect` print the most it allows in all. A day's total and a week's on one measure each count. An undo window is now a guarantee: a reversal a third party can refuse isn't an undo ([#405](https://github.com/yea-protocol/yea/issues/405)).
- **Distribution:** a Claude Code plugin (`/plugin marketplace add yea-protocol/yea`), an MCP registry entry (`io.github.yea-protocol/yea`), a Docker image (`ghcr.io/yea-protocol/yea`), and attested releases with SHA256SUMS.
- **Conformance vectors** for canonical JSON, keys, hashes, proofs, grants, Lens and token estimates.
- **Benchmark:** total input tokens against minified-JSON REST MCP across four tasks, with honest caveats. Measured on the tools `yea mcp` ships ([#297](https://github.com/yea-protocol/yea/issues/297)), YEA sends 2% fewer: its replies are mostly smaller, and its tool definitions, cut from 1,466 tokens to 1,136 ([#300](https://github.com/yea-protocol/yea/issues/300)), are still about 1.5 times REST's. The first published figure, 32% fewer, counted `yea test-drive`'s 4 generic tools, which `yea mcp` doesn't serve.
- **Security:** an adversarial audit's 15 findings are fixed, with regression tests. A threat model says what an approval proves ([#337](https://github.com/yea-protocol/yea/issues/337)): an answer to the approval form proves only what the client attests, since hooks, models and scripts can answer one, and a consent signed with `yea approve` is only as safe as the place the principal key is. So `yea mcp` never signs in the client, and has no `--approve-here` flag.
